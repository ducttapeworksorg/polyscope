# Updates are installed where electron-updater can, and offered as a download elsewhere

The installed app looks for newer releases on GitHub Releases. electron-updater applies them itself only for installers it knows how to replace: the AppImage, `.deb` and `.rpm` builds download an update in the background and restart into it when the user asks. It can't update an MSI install (its Windows updater replaces NSIS installs only), and macOS won't let it swap in an update to an app that isn't signed with a Developer ID, which v1 isn't. So on Windows and macOS the app asks GitHub's API for the latest release itself and, when it's newer, offers to open its download page. We kept the `.msi` rather than switching Windows to NSIS so that it installs the way administrators expect, and accept that Windows and macOS users run the new installer by hand. Once the app is signed with a Developer ID (planned alongside notarization, which v1 leaves out), macOS can move to electron-updater too; it needs a `zip` target beside the `dmg` for that, which is where electron-updater gets macOS updates from.
