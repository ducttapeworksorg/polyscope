# Portable copies rather than a browser mode

For users who can't install software but may run a downloaded executable (locked-down work machines), Windows also ships Polyscope as a Portable Copy: the same Electron app as a single portable `.exe` and as a `.zip` to extract anywhere. Some tools (Radar, for one) answer this need with a browser mode instead: one executable that starts a local server and opens the UI in the user's browser. That suits a single Go binary, but for Polyscope it would mean replacing the IPC bridge with HTTP and WebSockets, authenticating a localhost server that holds S3 secrets and kubeconfig access against other local processes and web pages, losing the native folder and file pickers and `safeStorage`, and giving up the identical rendering ADR 0002 chose Electron for. It would still be an executable the user downloads and runs, so it gets past no IT control a portable `.exe` doesn't.

Both portable forms ship because neither is safe on every locked-down machine. The `.exe` is a single file but unpacks itself into `%TEMP%` on every launch, which some policies forbid running from; the `.zip` runs in place and starts faster but takes an extra step. A Portable Copy keeps its data in the usual user-data folder, not beside itself: its secrets are encrypted with DPAPI for the Windows account, so a data folder carried to another machine couldn't decrypt them anyway. macOS and Linux get no portable build: the `.dmg` already runs without administrator rights, and the AppImage already runs without installing.
