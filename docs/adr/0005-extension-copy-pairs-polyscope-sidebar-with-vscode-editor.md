# An Extension Copy pairs Polyscope's sidebar with VS Code's editor

Alongside the desktop app (ADR 0001), Polyscope also ships as an Extension Copy for VS Code and compatible editors. The extension host runs the same core the Electron main process runs. Polyscope's own sidebar (the Sources tree and its dialogs) runs as a webview view, with a `postMessage` bridge standing in for the preload script's `window.polyscope`. Files open in VS Code's own editor through a read-only `FileSystemProvider`, so tabs, search, highlighting and split views come from VS Code. Following, Log Streams and Large Files open in Polyscope's own viewer in a webview tab instead, because VS Code's editor can't append live content, has no place for the log view's controls (Last N lines, timestamps, Follow), and has to load a whole file before showing any of it.

We considered three shapes. The whole Polyscope UI in one webview panel would have changed the least code, but it would have duplicated tabs and an editor that VS Code already provides. A fully native extension, with every file and log in VS Code's editor, would have lost Follow and the Large File Viewer, which are the reasons ADR 0001 kept a dedicated UI. The pairing we chose costs one prefactor of the desktop app's root component, so the sidebar and a single viewer tab can each be hosted on their own. A visible `polyscope.ownViewer` setting, on by default, routes everything to VS Code's editor when it is turned off. Follow is then hidden, and files over the open-anyway limit are refused rather than downloaded whole. The setting lets the fully native shape be compared in real use without building it separately.

An Extension Copy keeps its own Sources and settings rather than sharing an Installed Copy's, as a Portable Copy does. Its secrets go into VS Code's `SecretStorage`, which can't read what Electron's `safeStorage` encrypted for the desktop app, so shared Sources would arrive without their secret keys. It prefers to run in the remote extension host under Remote-SSH, WSL and Dev Containers, so a Local Filesystem Source, the kubeconfig and the AWS profiles are those of the remote machine. The desktop app already covers the user's own machine. VS Code restores editor tabs across reloads, so a restored `polyscope://` tab connects its Source; Polyscope's viewer tabs are live views and are not restored. The webviews map Polyscope's colour variables to VS Code's theme, apart from the colours that carry meaning (status and Environment colours). The editor's marketplace updates an Extension Copy, so it has no updater of its own.
